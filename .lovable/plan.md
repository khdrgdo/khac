# التدقيق الشامل لموقع NEXUS (قراءة فقط) كمرجع لتطبيق Android

## النطاق والقيود
- لن أعدّل أي ملف ولن أشغّل أي migration ولن أغيّر أي بيانات. كل الاستعلامات على قاعدة البيانات ستكون قراءة فقط.
- النتيجة النهائية تقرير واحد بالعربية يُحفظ في الملفات (`NEXUS_Audit_Report.md` ونسخة PDF) ولا يدخل ضمن كود الموقع.

## ما سيُفحص
1. **الصفحات**: الصفحة الرئيسية، الدخول، استعادة كلمة المرور، إكمال الملف، تغيير كلمة المرور، التغذية، المنشور، الملف الشخصي، المحفوظات، الصدارة، الرسائل والمحادثة، المقررات (الكل/مقرراتي/المقرر/إدارة المقرر)، لوحة الإدارة بكل تبويباتها.
2. **المكونات والمكتبات**: إنشاء المنشور وبطاقته وقائمته، المحرر والإشارات، البحث العام، الإشعارات (المتجر والإشعارات الفورية)، البطاقة المثبتة، إطارات البطاقات الشخصية وثيماتها، الرتب، المجهولية، طلبات تغيير الاسم، الخصوصية، التخزين، حماية الأجهزة، جسر الدخول للهاتف، تصدير CSV، مكونات الإدارة والمقررات.
3. **الخلفية**: كل الـ 41 migration، الجداول الحالية وسياسات RLS والصلاحيات الفعلية (عبر استعلام قراءة)، كل الدوال وtriggers، مخازن الملفات وسياساتها، الأدوار (طالب/أستاذ/أدمن/مشرف) وصلاحيات المشرف الست، والأدمن الرئيسي.
4. **المطابقة بين الواجهة والخلفية**: أي استدعاء في الواجهة لجدول أو دالة غير موجودة (مثلاً `name_change_requests` غير ظاهر في الجداول الحالية)، وأي ميزة تحفظ محلياً فقط بدل قاعدة البيانات، وأي سياسة تمنع ما تعرضه الواجهة.
5. **فحص تشغيلي محدود بالقراءة**: فتح الصفحات الأساسية في متصفح بحساب حقيقي لالتقاط أخطاء التحميل والحالات الفارغة، بدون إرسال أو حفظ أي شيء.

## بنية التقرير (لكل ميزة)
| الحقل | المحتوى |
|---|---|
| الاسم والمجال | مثل: المنشورات / الأسئلة / التعليقات ... |
| الصفحة والمكون | المسار والملف |
| تدفق الاستخدام | خطوات المستخدم |
| الصلاحيات | من يرى/ينشئ/يعدل/يحذف، وأين يُفرض (واجهة فقط أم قاعدة بيانات) |
| البيانات | الجداول، الدوال، المخازن، الاشتراكات الفورية |
| حالات الخطأ والفراغ | الموجود فعلاً والناقص |
| الحالة | **مؤكدة تعمل** / **تعمل جزئياً** / **واجهة فقط** / **معطلة** / **غير مؤكدة** مع الدليل (ملف:سطر أو نتيجة استعلام) |

المجالات المغطاة بالترتيب: التسجيل والدخول (الرقم الجامعي، جوجل، إكمال الملف، كلمة المرور الأولى، الاسترداد وOTP، التوثيق)، الملف الشخصي وتغيير الاسم والإعدادات والثيمات والبطاقات، المنشورات والأسئلة والإجابة المقبولة والتعليقات المتداخلة والتفاعلات والإشارات والصور والمجهول والحفظ والمشاركة والبلاغات، البحث، المراسلة (فردي/جماعي/حظر/إبلاغ/غير مقروء)، الإشعارات (داخلية/بث/فورية)، المقررات (روابط، ملفات، مهم، جدول، تحديثات، مناقشات، الأساتذة)، النقاط والرتب والتوثيق التلقائي والصدارة وفلاترها، البطاقة المثبتة (حدث/تصويت/مشاركة/استهداف)، لوحة الإدارة (إحصائيات، مستخدمين، أدوار، إنذار/إيقاف/حظر/حذف، مشرفون، أساتذة، بلاغات، كلمات محظورة، سجل النشاط، إعلانات، طلبات الاسم).

## الأقسام الختامية
- **تقرير الفجوات**: كل نقص مرتب حسب الخطورة (أمني / وظيفي / تجربة استخدام).
- **مخاطر أمنية** تؤثر على التطبيق (مثل دوال بلا تحقق من هوية المستدعي مثل `mark_conversation_read` و`delete_conversation` و`leave_conversation` و`get_unread_message_count` التي تقبل معرّف مستخدم من العميل) — تُذكر فقط إذا أكّدها الفحص.
- **مواصفات Android**: لكل شاشة في التطبيق: البيانات المطلوبة، الاستدعاءات (جدول/دالة) كما هي، القواعد، الحالات، وما يجب على التطبيق تجنّب الاعتماد عليه لأنه غير مكتمل في الموقع.
- **قائمة مرجعية** للعقود الثابتة: أسماء الدوال ومعاملاتها، الأنواع (التخصصات، الأدوار، التفاعلات، حالات البلاغ، الرتب وحدودها)، مسارات المخازن، والرابط العميق `com.nexus.app://login-callback`.

## ملاحظات تقنية
- الأدوات: `rg`/قراءة الملفات، استعلامات `select` فقط على `pg_policies` و`information_schema.role_table_grants` و`storage.buckets/objects policies`، فحص الأمان (قراءة)، وPlaywright بلا عمليات كتابة.
- الحجم كبير؛ سأوزّع الفحص على عدة مساعدين متوازيين (المصادقة والملف / المنشورات والبحث / المراسلة والإشعارات / المقررات / الإدارة والبطاقة المثبتة / الخلفية والسياسات) ثم أدمج وأتحقق من التناقضات بنفسي.
